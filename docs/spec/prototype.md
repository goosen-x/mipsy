# Спек прототипа mipsy

Зафиксирован 2026-08-11 по итогам гриль-сессии. Источники решений: `docs/research/konkurenty-vyvody.csv`, `docs/research/psypsy-landing.md`, `docs/research/psypsy-quiz.md`, `docs/research/references.md`.

## Цель

Прототип — не макет, а **живая приманка**: собирает реальные заявки клиентов и психологов. Проверяем спрос до постройки полного продукта. Возможен режим «психологов пока мало» — тексты лендинга не должны ломаться, если подбор занимает время.

## Модель продукта

- Независимая платформа, сторонние психологи, допуск через модерацию (критерии — TBD).
- Заработок — комиссия с сессии; в MVP оплат может не быть вовсе.
- **Подбор делает оператор вручную** по анкете клиента. Не каталог: клиент не роется в профилях сам. Простой переподбор — ключевое обещание.
- **Контакты психолога закрыты.** Вся связь клиент↔психолог — через платформу. В профиле и переписке контактов нет; в этическом кодексе психолога — запрет увода клиентов.
- Основной канал связи с клиентом — **телефон**, звонит оператор (отдельный человек).

## Роли

| Роль | Что делает в прототипе |
|---|---|
| Клиент | Проходит анкету-визард, оставляет телефон, ждёт звонка оператора |
| Психолог | Подаёт заявку, после одобрения ведёт профиль в кабинете, видит записи |
| Оператор | Видит список заявок клиентов и психологов, статусы, делает подбор руками |

## Страницы и флоу

### 1. Лендинг (структура по образцу PsyPsy, разбор — psypsy-landing.md)

1. Hero: обещание подбора («Мы подберём вам психолога») + CTA на анкету.
2. Боли клиента («не знаете, с чего начать»).
3. Как это работает, 3 шага: анкета → подбор → выбор времени.
4. Проверка психологов — мягкая формулировка, без цифр и процедур (критерии модерации не решены).
5. Примеры профилей: 2–3 карточки.
6. Темы — теги из справочника (те же, что в анкете).
7. FAQ (включая переподбор).
8. Футер: «Психологам» → заявка психолога; юридические страницы.

**Не делаем:** выдуманная статистика, цены (заглушка «стоимость сессии психолог указывает в профиле»), скидки, подписки, чат.

### 2. Клиентская анкета-визард (= регистрация клиента; разбор — psypsy-quiz.md)

Механика: один вопрос на экран, прогресс-бар, кнопка «назад», автопродвижение на одиночном выборе, «Продолжить» на мультивыборе/тексте, успокаивающие подсказки под чувствительными вопросами. Ответы копятся на клиенте, отправляются в конце.

Экраны (~14, ветка «для себя»; «для пары» и «для ребёнка» — карточки «скоро»):

1. Кому нужна поддержка (мне / паре — скоро / ребёнку — скоро)
2. Пол
3. Возраст
4. Опыт терапии (нет / краткосрочная / длительная)
5. Основная проблема (один выбор)
6. Темы (мультивыбор из справочника + «другое»)
7. Подавленность (частотная шкала)
8. Сон (частотная шкала)
9. Мысли о самоповреждении (частотная шкала) — **кризисная ветка**
10. Насколько состояние мешает жизни (4 ступени)
11. Предпочтения к психологу (пол/возраст)
12. Удобное время для сессий
13. Свободное поле «Расскажите, что происходит» — счётчик слов, мягкая мотивация написать больше
14. Имя + телефон + согласие ПД → экран «Оператор свяжется с вами»

**Кризисная ветка (обязательна):** при тревожных ответах на экране 9 — немедленно показать экран с экстренными контактами (телефоны доверия), не «следующий вопрос», как у PsyPsy. Анкету можно продолжить после.

Бюджетный вопрос — не включаем, пока не решены цены.

### 3. Профиль психолога (публичный; референс — анти-паттерн B17)

7 фиксированных секций, никакого свободного лендинга «о себе»:

1. Шапка: фото, имя, подход, опыт, формат, цена (заглушка до решения по ценам)
2. «О себе» — максимум 2–3 абзаца
3. Темы — теги из справочника
4. «Как проходят встречи»
5. Образование — с пометкой «проверено при модерации»
6. Мини-FAQ
7. Единственная кнопка «Записаться»

Без: контактов, дней рождения, семейного положения, счётчиков, скидок, форумов. Опциональный флаг «бесплатная встреча-знакомство 20 минут».

### 4. Кабинет психолога

- Заявка на модерацию: форма с широкими полями (документы, стаж, супервизия, личная терапия) — пороги допуска оператор решает вручную, глядя на заявки.
- После одобрения: редактирование профиля (в рамках 7 секций), список записей клиентов.
- Слоты расписания — после решения по календарю (запарковано).

### 5. Админка оператора

- Список клиентских заявок: анкета целиком, статус (новая / позвонили / подобран / отказ), пометки.
- Флаг кризисных анкет — видны сразу.
- Список заявок психологов: анкета, статус модерации (новая / одобрена / отклонена).
- Ручная привязка «клиент ↔ психолог» (подбор). Переподбор = смена привязки.
- Вход по паролю (один оператор, без ролей).

## Технический стек (Q17)

- **Next.js монолит**: TypeScript, App Router, Tailwind. Страницы + API-роуты + админка в одной кодовой базе.
- **БД: SQLite через Drizzle** на старте; миграция на Postgres позже без смены ORM.
- Деплой: **VPS пользователя** (91.197.99.37) за существующим nginx, как uspark — сначала порт/preview. Docker или node+pm2.
- «mipsy» — рабочее имя; финальное имя и домен — до запуска трафика (запарковано).

### Задел на будущее (не строим, но не блокируем)

- **Встроенные видеозвонки**: позже LiveKit/Jitsi self-hosted или SaaS SDK (Daily/Zoom). Сейчас — у сессии в модели данных поле «формат / ссылка на встречу», куда позже встанет ссылка на комнату.
- **Календарь слотов**: нужен, тип не решён. Модель данных сессии проектируем так, чтобы слот было куда прикрутить.

## Модель данных (набросок)

- `client_request` — анкета клиента: ответы всех экранов, имя, телефон, согласие ПД, флаг кризиса, статус, пометки оператора.
- `psychologist` — заявка/профиль: поля 7 секций + поля модерации (документы, стаж, супервизия, личная терапия), статус модерации, флаг встречи-знакомства.
- `topic` — справочник тем (общий для анкеты, профилей, лендинга).
- `match` — привязка клиент↔психолог, история переподборов.
- `session` — запись на сессию: клиент, психолог, время (пока текстом/датой, слот позже), формат/ссылка на встречу (задел под звонки).

## Вне скоупа прототипа

Оплаты и комиссия, чат, подписка, каталог с фильтрами, календарь слотов (дизайн), встроенные звонки, ветки анкеты «для пары»/«для ребёнка», атрибуция «откуда узнали», SMS/email-уведомления.

## Запарковано (решения пользователя, вернёмся)

Тип календаря · цены · критерии модерации · финальное имя и домен · оплаты в MVP · метрики успеха.
