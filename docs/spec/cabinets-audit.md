# Личные кабинеты: целевое устройство и аудит

Август 2026. Кабинеты (`/me`, `/cab`, `/admin`) переделывались несколько раз —
этот документ фиксирует, как код должен быть устроен, что расходилось с этим
на момент аудита и что было исправлено. Проверка: `npm test` (67 тестов на 15.08).

## Как должно быть устроено

Три слоя, каждый со своим швом; чем ниже слой, тем он глубже и тем проще его
проверить тестами.

**1. Чистые правила** — ни базы, ни Next, только вход и выход.
Это `auth-core.ts` (подпись сессии, проверка кода, право на патч аккаунта),
`datetime.ts` (московское время, правило 24 часов), `rules.ts` (кризис-флаг,
фильтр контактов, телефон). Тесты импортируют этот код напрямую. Правило
существует в одном месте: если оно нужно и форме, и экшену, и тесту — все
трое импортируют одну функцию, а не держат копии.

**2. Домен с базой параметром** — `booking.ts`: весь жизненный цикл слота
(free → booked → done | no_show → снова free). Модуль не импортирует ни
`@/db`, ни Next: базу передаёт вызывающий, поэтому тесты гоняют его против
временного SQLite с настоящими миграциями. Относительные импорты внутри —
с расширением `.ts`: файл загружают и Next, и `node --test`.
Все переходы статусов слота живут только здесь; экшен, который сам пишет
`UPDATE slots SET status=...`, — регрессия.

**3. Экшены — тонкие переходники.** `"use server"`-файл кабинета делает три
вещи: узнаёт, кто пришёл (сессия/оператор), зовёт домен, а по возвращённым
данным рассылает уведомления и делает `revalidatePath`. Бизнес-проверок в
экшенах нет — если экшен сравнивает статусы слота или считает часы, правило
уехало не туда.

Уведомления остаются в экшенах сознательно: домен возвращает «что произошло
и кого предупредить» (`slot`, `psy`), а отправка — побочный эффект уровня
оркестровки. Так домен тестируется без SMTP.

## Что расходилось и исправлено

- **Фильтр контактов был только на клиенте.** `updateProfile` сохранял
  телефон/телеграм в профиле, если дернуть экшен мимо формы. Теперь правило
  в `rules.ts` и проверяется на сервере тоже.
- **Чужой почтой можно было переименовать чужой аккаунт.** `linkAccount`
  патчил имя и телефон существующего аккаунта по данным любой анкеты/заявки.
  Теперь `accountPatch` (auth-core) разрешает патч только владельцу сессии.
- **Бронь оператором оставляла клиента без ссылки на встречу** и позволяла
  записать в прошлое: `bookSlotForClient` не ставил `meetingLink` и не
  проверял время. Теперь идёт через `takeSlot`, как все остальные брони.
- **Освобождение слота не стирало `meetingLink`** (отмена, перенос,
  переподбор, операторский `freeSlot`) — следующая бронь могла показать
  чужую ссылку. `releaseSlot` чистит всё клиентское.
- **Переподбор молча снимал брони** — психолог не узнавал, что время
  освободилось. Теперь `requestRematch` шлёт «встреча отменена» по каждой
  снятой брони.
- **Проверка кода входа жила двумя копиями** (аккаунты и новые адреса) —
  объединена в `checkCode` с фиксированным порядком: лимит попыток → срок →
  сравнение.
- **`rules.test.mjs` проверял собственную копию правил** — изменение src его
  не ломало. Переписан на импорт настоящего кода.
- **Расписание принимало мусор**: окна в прошлом и «время» вида `25:99`.
  `openSlots` пропускает прошедшие времена и валидирует ЧЧ:ММ по диапазону.
- Отмена/перенос теперь явно требуют `status='booked'` (раньше держалось на
  неявных инвариантах), пароль оператора сравнивается через `timingSafeEqual`.

## Дополнено позже (август 2026): кабинет админа

Общий пароль оператора упразднён, кабинет переехал `/op` → `/admin` (старые
адреса редиректят). Админ — обычный аккаунт с ролью `accounts.is_admin`:
вход по коду с почты, как у всех. Первого админа назначает `ADMIN_EMAILS`,
дальше роли раздаются на `/admin/team` (аккаунт должен существовать; себя
разжаловать нельзя). `admin_log` стал именным (`actor_account_id`), секрет
сессии — отдельный `SESSION_SECRET` (миграция 0009, `OPERATOR_PASSWORD`
остался запасным секретом, чтобы действующие сессии не слетели).

## Замечено, но не правилось (бэклог)

- **Без `SESSION_SECRET` (и `OPERATOR_PASSWORD`) секрет сессии — константа
  `mipsy-dev-secret`**: на сервере без переменной сессии подделываются.
  Стоит падать при её отсутствии в проде.
- ~~`reviews.slot_id` без уникального индекса~~ — закрыто 15.08: миграция
  `0015_integrity.sql` добавила `reviews_slot_unique`, двойной отзыв блокируется
  схемой (есть тест).
- ~~Переподбор не деактивирует старые `matches`~~ — закрыто 15.08:
  `requestRematch` гасит все активные предложения через `deactivateMatches`
  (есть тест).
- **Кука сессии бессрочна по подписи** (ограничена только `maxAge`), отзыва
  сессий нет. Приемлемо для MVP, важно помнить при инцидентах.
- Пометка `isIntroCall`, поставленная психологом на своё окно, теряется при
  освобождении брони — историческое поведение, сохранено как было.
