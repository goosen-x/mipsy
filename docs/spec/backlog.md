В `docs/deploy.md` деплой переписан на вызов этого скрипта вместо ручного `docker run`.
Осталось необязательное: вынести переменные в `--env-file /root/mipsy.env`, чтобы
секреты не жили в теле скрипта. История ниже — чтобы грабли не повторились.

Обнаружено 21.08. Скрипт `/root/mipsy-run.sh` на VPS задуман как единственное
место, где живут переменные запуска («обновлять здесь, а не в командной строке»),
но часть переменных задавали руками мимо него. В работающем контейнере есть
`ADMIN_EMAILS`, `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`, а в скрипте их нет.

Скрипт начинается с `docker rm -f mipsy`, поэтому первый же запуск ради обновления
пересоздаст контейнер без этих переменных: **админка закроется для всех** (роль
из `ADMIN_EMAILS` пропадёт, а админов с ролью в базе может не остаться) и
отвалятся кнопки оплаты. Перезагрузка сервера не опасна — `--restart unless-stopped`
поднимает контейнер с прежним окружением; опасен именно повторный прогон скрипта.

Сделать: дописать недостающие `-e` в `mipsy-run.sh` (значения снять с живого
контейнера через `docker inspect`), сверить с ним раздел «Устройство» в
`docs/deploy.md` и там же зафиксировать правило — любая переменная только через
скрипт. На будущее надёжнее вынести переменные в `--env-file /root/mipsy.env`,
чтобы секреты не жили в теле скрипта и не терялись при правках.

## Отложено по аудиту 15.08

Полный отчёт аудита — `docs/spec/audit-report-15-08.md` (страница `/admin/report`
удалена 17.08 по решению пользователя). Здесь — только осознанно отложенное:

- ~~**METHOD:CANCEL для старых .ics.**~~ Сделано 17.08: при отмене и переносе
  во все письма вложен отзыв события (METHOD:CANCEL, SEQUENCE:1) с тем же UID;
  UID стал уникальным на бронь (`bookingUid(slotId, clientRequestId)`), а не на
  окно — отзыв не задевает новую бронь того же окна. Клиент при своей отмене
  теперь тоже получает письмо (носитель отзыва). Приглашения, отправленные до
  17.08 со старой схемой UID, отозваны не будут — таких броней единицы.
- **SESSION_SECRET с фолбэком на константу** — в проде секрет задан, но правильно падать
  при его отсутствии, а не подписывать сессии `mipsy-dev-secret`.
- **Кука сессии без срока внутри подписи**, отзыва сессий нет — приемлемо для MVP,
  критично при инцидентах.
- **Статусы-enum без CHECK в схеме**; нет статусов «черновик»/«на доработку» у психолога
  и «форс-мажор» у встречи — требует миграций-перестроек и продуктовых решений.
- **Мёртвые колонки** (format, price, intro_call_enabled, cabinet_token, client_token) —
  не удалены: перестройка таблиц SQLite ради нуля пользы; помечены в схеме.
- **Дубли мелких выборок** («психолог по аккаунту» ×5, шейпы контактов, SITE_URL ×4)
  и 600-строчный admin/controls.tsx — сводить по мере правок этих мест.
- **БД-часть auth не тестируется** (linkAccount, коды, троттлинг) — заперта
  server-only-импортами; нужен рефактор «база параметром» по образцу booking.ts.
- **Нет транзакции вокруг «заявка + бронь + matches»** в bookFirstSession — компенсация
  есть, атомарности нет.
- **notifications.recipient_phone NOT NULL с сентинелом ""** — врёт для будущих
  SMS-интеграций; перестройка таблицы.
