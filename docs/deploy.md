# Деплой mipsy на VPS

Прототип живёт на VPS `91.197.99.37` в Docker-контейнере и доступен по адресу **https://mipsy.mskacademy.ru**

## Домен и HTTPS

- A-запись `mipsy` в зоне `mskacademy.ru` (панель reg.ru) → `91.197.99.37`.
- nginx: `/etc/nginx/sites-available/mipsy.conf` + симлинк в `sites-enabled` — по образцу соседних сайтов (snippets `security-headers` и `proxy-nextjs`, `limit_req zone=req_limit`), проксирует на `127.0.0.1:8081`.
- Сертификат Let's Encrypt выпущен certbot'ом (`certbot --nginx -d mipsy.mskacademy.ru --redirect`), продление автоматическое. HTTP отдаёт 301 на HTTPS.
- Контейнер слушает **только 127.0.0.1:8081** — снаружи порт закрыт, весь трафик идёт через nginx по HTTPS.
- Домен временный: `mipsy.mskacademy.ru` — поддомен чужого бренда. Перед платным трафиком стоит взять собственный домен (`mipsy.ru` на момент проверки 2026-08-12 свободен) — тогда достаточно повторить два шага: A-запись и `certbot --nginx -d <домен>`.

## Устройство

- Образ собирается из `Dockerfile` (multi-stage: npm ci с python3/make/g++ для better-sqlite3 → next build standalone → лёгкий рантайм).
- При старте контейнер запускает `scripts/migrate.mjs`: применяет SQL-миграции из `drizzle/` (журнал — таблица `_migrations`) и сидит справочник тем. Использует только better-sqlite3 — drizzle-orm в standalone не попадает.
- БД: SQLite в volume `/root/mipsy-data` на хосте (`/app/data/mipsy.db` в контейнере) — переживает пересборки.
- Админка живёт на `/admin` (бывший `/op`, старые адреса редиректят). Общего пароля больше нет: админ входит как все — по коду с почты, а роль лежит на аккаунте (`accounts.is_admin`). Первого админа назначает `-e ADMIN_EMAILS=адрес[,адрес]` — этим почтам роль даётся без записи в базе; дальше роли раздаются со страницы `/admin/team`.
- `-e SESSION_SECRET=…` — секрет подписи сессий кабинетов; после его смены все входы слетают и людям придётся войти заново. Для совместимости со старыми установками, где секретом был пароль оператора, поддерживается запасной `OPERATOR_PASSWORD` — если задан только он, сессии остаются живыми.
- `-e SITE_URL=https://mipsy.mskacademy.ru` — подставляется в ссылки внутри писем и SMS.
- SMS: `-e SMS_LOGIN=… -e SMS_PASSWORD=… [-e SMS_SENDER=…]` (провайдер smsc.ru). Без них уведомления копятся в `/admin/notifications`, админ отправляет вручную.
- Загруженные фото психологов лежат в `/root/mipsy-data/uploads` (тот же volume, что и база) и отдаются роутом `/uploads/[name]`.

## Бэкапы

`/root/mipsy-backup.sh` (исходник — `scripts/backup.sh`) запускается кроном ежедневно в 04:00: делает `VACUUM INTO` без остановки сервиса, жмёт gzip, отдельно архивирует загруженные фото, хранит 14 дней в `/root/mipsy-data/backups`. Лог — `/var/log/mipsy-backup.log`. Проверка восстановления: распаковать копию и открыть её через `docker run --rm -v …:/t mipsy node -e "…"`.

## Мониторинг и алерты

`/root/mipsy-healthcheck.sh` (исходник — `scripts/healthcheck.sh`) раз в 5 минут по крону дёргает `/api/health` (отвечает приложение + читается база) и считает новые ошибки в журнале за час. Лог — `/var/log/mipsy-health.log`. Письма-алерты уходят, только если в `/root/mipsy-alert-email` записан адрес; файла нет — алерты остаются в логе. Журнал ошибок приложения виден админу в `/admin/errors`, именной журнал действий админов — в `/admin/audit`.

## Вход в кабинеты

Кабинеты живут по постоянным адресам `/me` (клиент) и `/cab` (психолог), секрета в ссылке нет. Вход — на `/login`: человек вводит почту, получает письмом шестизначный код (живёт 15 минут, пять неверных попыток блокируют его до нового запроса) и дальше работает по подписанной куке-сессии на 60 дней. Пароля нет намеренно: нечего хранить и нечему утекать.

**Вход и регистрация — один шаг** (паттерн sign-in-or-up, как у Clerk, Supabase и Firebase). Код уходит на любой корректный адрес, и экран для знакомой и незнакомой почты одинаковый, поэтому перебором адресов нельзя узнать, кто обращался к психологам. Развилка происходит после того, как человек доказал, что почта его: есть аккаунт — ведём в его кабинет, нет — заводим аккаунт и ведём в новый кабинет `/me`, где подбор психолога запускается кнопкой. Анкета доступна только после входа (`/anketa` без сессии редиректит на `/login`), почту она не спрашивает — берёт подтверждённую из сессии. Коды для адресов без аккаунта лежат в отдельной таблице `email_codes` (живут сутки) — мусорные записи в `accounts` от чужого перебора не появляются.

**Все формы с персональными данными — за входом**: анкета, заявка психолога и запись из каталога требуют сессию, почту берут из неё и не доверяют полю из формы. Профили психологов и каталог остаются публичными — вход просят только в момент записи. Аккаунт создаётся единственным способом — подтверждением кода на `/login` (плюс админ может завести аккаунт старой телефонной заявке, вписав почту в её карточке).

Чтобы чужой ящик нельзя было засыпать письмами, на один адрес уходит не больше **пяти писем в час** (считаются запросы, а не успешные отправки); дальше человек видит просьбу подождать. Ограничения по IP пока нет — оно в бэклоге.

Из этого следует эксплуатационное требование: **без рабочего SMTP в кабинет никто не войдёт** — включая админа (его страховка — `ADMIN_EMAILS` плюс код из базы: `accounts.login_code`). Если письмо не ушло, код виден админу в `/admin/notifications` — можно продиктовать по телефону. Старые ссылки `/me/<token>` и `/cab/<token>` из ранее отправленных писем продолжают работать как редирект на вход; доступа сами по себе они больше не дают.

Каждая попытка входа пишется в журнал `login_log` и видна админу в `/admin/notifications` → «Попытки входа»: введённый адрес, время и что именно случилось — код отправлен, письмо не ушло (с причиной), такой почты у нас нет, код просрочен, попытки исчерпаны, вошёл. Это единственный способ ответить на «мне не приходит код»: если аккаунта с таким адресом нет, письма не было вовсе. Записи старше 30 дней удаляются автоматически. В `error_log` этот журнал намеренно не пишется — по нему считаются алерты healthcheck.

Заявкам, заведённым до этой схемы, почты может не быть — тогда в карточке заявки у оператора есть поле «Открыть доступ»: он спрашивает адрес по телефону и вписывает, заявка привязывается к кабинету.

## Тесты

`npm test` — проверки на node:test: весь жизненный цикл слота через `src/lib/booking.ts` на настоящей SQLite (бронь, гонка, перенос, отмена, исходы), правила платформы из `src/lib/rules.ts`, московское время и правило 24 часов, подпись куки сессии, проверка кода входа, право на патч аккаунта, разбор `ADMIN_EMAILS` и перенос старой базы на аккаунты (миграции прогоняются на копии дореформенной схемы). ## Обновление версии

```bash
# из /workspace/mipsy (контейнер разработки):
tar czf - --exclude node_modules --exclude .next --exclude .git --exclude data --exclude .env.local . \
  | ssh -i /root/.ssh/id_ed25519_vps root@91.197.99.37 \
    'rm -rf /root/mipsy-src && mkdir -p /root/mipsy-src && tar xzf - -C /root/mipsy-src'

ssh -i /root/.ssh/id_ed25519_vps root@91.197.99.37 '
  cd /root/mipsy-src && docker build -t mipsy . &&
  docker rm -f mipsy &&
  docker run -d --name mipsy --restart unless-stopped -p 127.0.0.1:8081:3000 \
    -v /root/mipsy-data:/app/data -e SESSION_SECRET=<секрет> -e ADMIN_EMAILS=<почта админа> mipsy
'
```

При изменении схемы БД: `npx drizzle-kit generate` локально (создаст новый файл в `drizzle/`), закоммитить — контейнер применит его при старте. Миграция `0005_accounts.sql` заодно переносит данные: заводит аккаунты по почтам из заявок и профилей (регистр не важен, одна почта — один аккаунт) и удаляет колонки `access_code`.

## Локальная разработка

```bash
npm install
node scripts/migrate.mjs   # схема + перенос данных + справочник тем в data/mipsy.db
printf 'SESSION_SECRET=dev\nADMIN_EMAILS=admin@example.com\n' > .env.local
npm run dev
```

Без SMTP локально письма не уходят — код входа виден в `/admin/notifications` или прямо в базе (`accounts.login_code`, для новых адресов — `email_codes.code`).

## Заметки

- scp/sftp на VPS не работают (restrict в authorized_keys) — только tar поверх ssh-exec.
- nginx на VPS боевой и чужой — не трогаем; наружу смотрит порт 8081 напрямую через docker-proxy.
- Секреты (`SESSION_SECRET`, SMTP, SMS) в репозиторий не коммитим.
